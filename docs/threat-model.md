# Threat model and test boundaries

The lab considers two published MCP SDK failure modes. A crafted resource URI can cause excessive backtracking when an exploded URI-template variable is matched. A local unauthenticated HTTP MCP server without Host validation can be exposed to DNS-rebinding conditions described in the upstream advisory. The [URI advisory](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-cqwc-fm46-7fff) and [Host advisory](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-w48q-cv73-mx4w) define the upstream impact and affected versions.

The URI case imports actual pinned SDK packages in child processes. Only checked-in case IDs are accepted. The parent limits each child to 2 seconds and 64 KiB combined output. It records a ready signal after import and construction so matching time is separated from startup. The nonmatching repeated-comma input exercises the published regex defect while valid comma-delimited controls detect an over-restrictive patch.

The Host case creates actual SDK 1.23.1 transport and SDK 1.24.0 Express-app/transport instances. Servers bind to `127.0.0.1` on port `0` and close after each probe. Requests use only synthetic Host values under `probe.invalid`, `localhost`, or `127.0.0.1`; there is no DNS server, browser, outside host, or access to another application's listener. A marker immediately before the SDK transport shows whether the app's global middleware allowed a request to reach the route. The 406 response on allowed requests comes from the SDK transport's missing `Accept: text/event-stream`, which is intentional; the test's security assertion is route reachability versus 403 rejection.

For HTTP/1.1 without a Host header, Node rejects the request with 400 before Express. The network case therefore does not prove the SDK middleware's missing-Host behavior; a separate direct middleware test checks that behavior. The legacy and protected configurations differ in how Express is constructed. Upgrading a custom Express app alone does not automatically add the new helper's Host middleware.

Evidence output uses a finite schema and redacts paths and sensitive field names. The report contains package versions, npm lockfile integrity, runtime, input lengths/shapes, result states, and limitations. It does not contain raw request headers, secrets, account traffic, or source from a private project. Timing values are machine-specific. These tests cannot certify the general security of any SDK release or demonstrate an end-to-end exploit.
